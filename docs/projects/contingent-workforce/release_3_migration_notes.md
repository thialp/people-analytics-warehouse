# Release 3: what changes in the published workbooks

Arcadia Systems is fictional and all data is synthetic.

Release 3 changes the data under Dashboards #1 and #2 in two steps. This page lists, phase by phase, every field, calc and value a workbook will notice, so the republish (phase 10) is a checklist rather than a hunt. The build books in `docs/projects/headcount-fte-walk/` and `docs/projects/compensation-walk/` describe the dashboards **as published on release 2** and are left as they are until phase 10.

## Phase 1: part-time removed (2026-10-14)

Every employee is 1.0 FTE. People, hires, exits, moves, promotions, seats and requisitions are **identical to release 2** (the generator keeps every random draw; only FTE is forced to 1.0). What changes is FTE and cost.

### What changed in the data

| Item | Release 2 | Release 3 | Why |
|---|---:|---:|---|
| Job history records | 98,028 | 96,129 | 1,899 `FTE Change` records no longer exist |

| FY26 cost bridge growth, nominal | +$229.5M (+7.4%) | +$238.8M (+7.5%) | |

### Dashboard #1, Headcount & FTE Walk

After Edit Custom SQL (or Replace Data Source) on release 3:

1. **`Part Time Headcount` turns red.** Calcs that use it: `K Close PT`, `K Part Time Gap`, `K Gap T`, `KPI 2 Note` ("924 part-time · 261.0 below headcount"), `TT Part Time`, `TT Level PT`. The KPI 2 note has nothing left to say: FTE equals headcount.
2. **The FTE Changes bar disappears** on its own (no rows). `Show Category`, `WF FTE Chg` and the `FTE Changes` tooltip branch become dead code.
3. **The Headcount / FTE toggle (`Measure`) shows the same numbers both ways.**

Proposed for phase 10, not done yet: replace the Measure toggle with a **worker type** switch (Employees · Contingent · Total workforce) once contingent workers are in the walk (phase 6), and use the KPI 2 note for the contingent share. Until then, a republish on phase 1 data is possible but not worth it.

### Dashboard #2, Compensation Walk

1. **The expanded waterfall shows 12 steps, not 13.** Calcs that name `FTE Changes` (`TD Key`, `TD Why`, the `step` alias) keep working; the branch is never reached.
2. **Every dollar value moves** (table above). The check table `docs/projects/compensation-walk/expected_values.md` is regenerated by the pipeline.
3. Nothing turns red: no column was removed from the walk.

### Validation scripts (`sqlserver/`)

Refreshed to release 3 values: `05` (job history rows; control totals comment), `06` (walk rows; FY23 and FY26 expected tables), `08` (seat records), `10` (walk rows; closing FTE; the part-time check is now "lines where FTE differs from headcount = 0"), `11` (footprint office rows; closing FTE). `07` and `09` are unchanged.
